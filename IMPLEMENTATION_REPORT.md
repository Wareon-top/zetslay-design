## Проверки (фактический вывод)

- Мобильная ширина 390/320: нет горизонтальной прокрутки на главной, заказах, лотах, сообщениях, аналитике, финансах, автоматизации, плагине (вкладки прокручиваются внутри своей полосы).
- `python -u -X utf8 scripts/qa-cabinet-v3.py` → `{"passed": 125, "total": 125, "runtimeErrors": [], "missingAssets": []}` (до моих правок падал на повторном сохранении профиля).
- `node --test app/cabinet-v3/model.test.mjs` → 5/5.
- `npm run validate` → passed.
- `node --test app/plugin-page.test.mjs app/stars-relay.test.mjs` → 25 прошли, 3 упали: «focused rarity deployment … VPS cover layout». Причина — Windows: тест строит временный путь через `URL.pathname` (`/C:/...`, ENOENT в mkdtemp) и запускает `python3`; он рассчитан на Linux, как и пропущенный POSIX-тест установщика. С переносом дизайна не связано.
- `python -m pytest deploy/test_cabinet_v3.py` → 11 passed, 1 skipped (POSIX-права проверяются только на Linux).
- Установщик на копии `reviews/cabinet-public-host-20261114` (из index убраны прежние неуправляемые подключения cabinet-v3, иначе установщик по замыслу отказывается): установка прошла, повторный запуск не дублирует подключения, откат вернул index. Первая попытка была честно отклонена из-за CRLF в рабочей копии — исправлено.
- Навигация вручную в браузере: клик по карточке, back/forward, прямой hash, `setView` с другим плагином — страница плагина открывается корректно.

## Для Codex

- Публикация: только через установщик и только после решения владельца. На VPS уже не должно быть неуправляемых подключений cabinet-v3, иначе установщик откажет (так задумано).
- Заполненные состояния главной/заказов/сообщений/лотов/событий сверены на синтетическом сервере (см. выше). Формы ответов взяты из того, что реально читают контроллеры хоста; `store-tools`, склад и финансовый отчёт теперь тоже есть в синтетическом сервере (форма — по тому, что проверяют контроллеры). Для QA-фикстур репозитория по-прежнему нужны заказов/сообщений/лотов/store-tools в `previews/cabinet-live-review/fixtures.json` (их форму стоит взять из реальных ответов API, а не придумывать).
