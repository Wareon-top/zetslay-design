# Обновление ZetSlay — первый выпуск по конкурентному аудиту

Дата: 3 ноября 2026 года. Это первый реализованный пакет стратегии, а не заявление о выполнении всей программы на 90 дней.

## Состав

- Открытое демо /demo/ без регистрации и ключа: обзор, заказы, переписка, лоты, финансы, пример проверки правила, подготовка к подключению.
- Повторное использование учебных экранов существующего кабинета. Изоляция публичного примера от пользовательской сессии проверяется тестом с запрещённым чтением authState.
- Раздел /docs/: подключение FunPay, первая выдача и диагностика. Отдельная /pricing/ с действующими ценами и дополнительными расходами. Новые страницы включены в sitemap; синтетическое демо закрыто от индексации.
- Кнопка демо и инструкции на главной. Существующая иллюстрация, бренд и основная структура сохранены.
- Проверка несохранённых автоответов в настоящем кабинете: выбранное правило, пересечения, подстановка имени, ограничения. Использует новый API backend; на старом API показывает понятное сообщение.
- Дополнительное пояснение требований и расходов в мастере подключения.
- Точечная подготовка и установка с резервной копией, проверкой известных участков и восстановлением при ошибке записи.

## Основа и совместимость

Рабочая основа frontend — ветка codex/landing-light-dark-redesign, ревизия d37e6b1 от 1 ноября. Это более поздняя версия, чем ранее сохранённая 71daa48. Backend — рабочая ветка codex/funpay-readonly-web-connector, основа cb3c592 от 2 ноября.

Публичный HTML действующего кабинета содержит добавленные установщиками подключения, которых нет в исходном app/index.html. В частности, проверено присутствие basic-automation.js и workspace-upgrade.js на действующем сайте. Это подтверждает подключение файлов, но не исполнение реальных заказов.

Установщик сохраняет действующий HTML; не заменяет app/app.js, настройки API, локальные обложки, остальные модули, тарифы, пользовательские данные и включённые сценарии. Несовместимая версия изменяемого участка останавливает подготовку.

## Проверка

- npm run test:upgrade — поведение учебного кабинета, публичная изоляция, проверка правил, защита от запоздалых ответов, мастер и ссылки.
- npm run check:guides — соответствие пяти статических страниц исходному генератору.
- npm run validate — штатная проверка репозитория и ссылок, расширенная на новые публичные разделы.
- python3 deploy/stage-competitive-release.test.py -v — сохранение локальных правок, повторный запуск, отказ на неизвестной реализации, откат частичной установки на Linux.
- Подготовка также проверена на копиях публичных index.html, app/index.html, cabinet-demo.js и connection-wizard-ui.js действующего сайта от 3 ноября.
- В браузере проверены основные взаимодействия, все семь разделов демо на ширине 390 px и настольная компоновка. Это не полный аудит доступности и не тест реального магазина.

Полный локальный прогон старых тестов в Windows выявил проверки, использующие Linux bash или URL.pathname как файловый путь. Новые и затронутые сценарные проверки запускаются отдельно; общий Linux-прогон выполняет существующий workflow Verify cabinet and landing. Результаты CI нужно смотреть на конкретном SHA.

## Установка на VPS

Для согласованного применения подготовлен deploy/start-competitive-release.sh. Он получает фиксированную пару ревизий, сначала проверяет frontend, затем обновляет текущий API-образ с проверкой зависимостей и применяет точечные изменения сайта. Запускается как отдельная systemd-задача; разрыв SSH не останавливает работу. Вызов: bash путь-к-launcher полный-SHA-frontend. Факт запуска не равен успешному завершению — дождаться финальной строки в журнале и проверки страниц.

Сначала установить и проверить парный backend-выпуск с endpoint POST /api/v1/store-tools/automation/preview. Затем подготовить frontend из фиксированного SHA. Обновление рабочей ветки или создание PR само по себе не считается установленным выпуском.

В /opt/zetslay-site получить ветку выпуска, зафиксировать FETCH_HEAD и распаковать её в отдельный каталог, не выполняя checkout/reset поверх работающего сайта:

```bash
cd /opt/zetslay-site
git fetch origin codex/competitive-upgrade-20261103
revision=$(git rev-parse FETCH_HEAD)
source_dir=$(mktemp -d /root/zetslay-public-release.XXXXXX)
git archive "$revision" | tar -x -C "$source_dir"
python3 "$source_dir/deploy/apply-competitive-release.py" --site /opt/zetslay-site --source "$source_dir"
```

Последняя команда только проверяет подготовку. После успешной проверки установка того же пакета:

```bash
python3 "$source_dir/deploy/apply-competitive-release.py" --site /opt/zetslay-site --source "$source_dir" --apply
```

Установщик сообщает каталог резервной копии и сохраняет release-files.json со списком новых файлов и контрольными суммами. При ошибке записи возвращает прежние файлы и удаляет только созданные им файлы. Неизвестные локальные версии не перезаписываются. Применение на настоящем VPS этим документом не подтверждается.

После установки проверить /demo/, /docs/, /pricing/, вход, существующие рабочие страницы и проверку несохранённого правила. Публичное демо не обращается к API. Проверка правила в кабинете обращается к API, но не отправляет сообщение и не сохраняет конфигурацию.

## Следующие этапы

После выпуска измерить переход в демо, завершение подключения и первое полезное действие. Следующий продуктовый пакет: диагностика реальных исключений, известная маржа заказа, два законченных сценария выдачи/аренды и пилот с магазинами. Новые площадки, переписывание платежей, изменение цен и автоматические действия в реальных магазинах в этот пакет не входят.
