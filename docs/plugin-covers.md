# Обложки плагинов

Баннеры в каталоге и на странице плагина используют рамку 16:9 и `object-fit: contain`: всё изображение видно, пустые поля заполняются тёмным фоном. Пропорции исходника сохраняются. В каталоге статус и кнопка администратора находятся вне изображения.

Файлы:
- `app/plugin-cover.css`: размеры рамок, вписывание изображения и положение элементов.
- `app/plugin-cover.js`: PNG / JPEG / WebP до 10 МиБ на входе, до 2 МиБ для сохранения. Оригинал до 2 МиБ и не более 4096 px по длинной стороне сохраняется без изменения байтов. Крупные файлы уменьшаются пропорционально до 2560 px, WebP quality 0.92, без увеличения маленьких изображений. Прозрачность сохраняется. Если файл всё ещё велик, выполняются до пяти уменьшений размеров с тем же качеством; SVG и внешние URL не принимаются.
- `app/app.js`: `compressPluginCover` делегирует подготовку новому модулю; `renderPlugins` выносит элементы за пределы баннера.
- `app/plugin-page.js`: одинаковая рамка на подробной странице, допустимый размер обложки и подсказка для администратора.
- `zetslay-core/services/control-plane/src/plugin-catalog.mjs`: проверка растрового data URL и точного размера декодированных данных до 2 МиБ.
- `zetslay-core/services/control-plane/src/http-server.mjs`: только POST каталога принимает JSON до 3 МиБ. Остальные лимиты API не изменены; запись по-прежнему доступна только администратору.

Это изменение не восстанавливает детали старых пережатых обложек. После обновления API и кабинета загрузите исходное изображение повторно. Для рамки без полей используйте изображение 16:9, например 1920×1080; другие пропорции будут полностью видны с полями.

## Проверка

```sh
node --test app/*.test.mjs
python3 deploy/stage-plugin-covers-ui.test.py
```

В основном репозитории:

```sh
node --test services/control-plane/test/plugin-catalog.test.mjs services/control-plane/test/control-plane.test.mjs
```

Тесты обработки используют заглушки браузерных bitmap/canvas/FileReader API; проверяют сохранение оригинала, размеры, отсутствие обрезки, качество кодирования, освобождение bitmap, границы и ошибки. Серверные тесты отправляют настоящий HTTP-запрос с обложкой 2 МиБ и проверяют возврат тех же байтов, права и лимиты. Они не заменяют визуальную проверку в браузере.

## Обновление VPS

Сначала API (нужно увеличить прежний лимит обложки). Выполнить на основном VPS:

```sh
bash <<'SH'
set -euo pipefail
cd /opt/zetslay
git fetch origin codex/funpay-readonly-web-connector
script=$(mktemp)
trap 'rm -f "$script"' EXIT
git show FETCH_HEAD:deploy/update-plugin-covers-api.sh > "$script"
bash "$script"
SH
```

Затем кабинет:

```sh
bash <<'SH'
set -euo pipefail
cd /opt/zetslay-site
git fetch origin codex/landing-light-dark-redesign
script=$(mktemp)
trap 'rm -f "$script"' EXIT
if [ ! -f app/plugin-page.js ]; then
  git show FETCH_HEAD:deploy/update-plugin-ui.sh > "$script"
else
  git show FETCH_HEAD:deploy/update-plugin-covers-ui.sh > "$script"
fi
bash "$script"
SH
```

Установщик кабинета проверяет подготовленные файлы в Node 22 до записи, сохраняет локальные исправления и другие разделы, создаёт резервную копию. API обновляется только при отсутствии изменений отслеживаемых файлов; неотслеживаемые резервные env-файлы не мешают. После Ctrl+F5 повторно загрузить оригинал обложки и проверить баннер в каталоге и на подробной странице. Настройки сервиса менять не требуется.
