# Профиль

Вместо отдельных страниц Telegram и Безопасность кабинет содержит `#profile`.
Данные аккаунта, магазин, Telegram-бот, сессия, тариф и карточка автора собраны
в одном разделе. Старые ссылки `#telegram` и `#security` переходят на профиль.
Кнопка аккаунта в верхней полосе и боковой панели открывает профиль после входа.

`profile.js` использует существующие `state`, `authState`, `apiRequest`,
`storeIdentityModel`, `storeIdentityAvatar` и мастер `setModal`. Управление
подключением открывает этот мастер, сохраняя его существующие проверки прав
и ограничения на изменение уже подключённого магазина. Бот показан как
«Привязан», когда сервер подтвердил привязку; это не обещание его uptime.

Редактируемые данные сохраняются через `/api/v1/profile` с версией. Публикация
карточки выключена по умолчанию. Имя, фото и биография становятся доступны
другим только после включения переключателя и сохранения. Аватарка сохраняется
без повторного сжатия; ограничение 256 КБ. Нет обязательной почты для Telegram.

Страница `#authors/<authorId>` обращается только к `/api/v1/authors/:authorId`
и использует отдельный `publicAuthorMarkup`. Личные данные не входят в эту
карточку. Это фундамент для ссылок на авторов в будущем маркетплейсе; продажи,
отзывы, рейтинги и подкаталог маркетплейса ещё не созданы.

Обновление VPS: сначала обновите backend и выполните миграции стандартным
`docker compose ... up -d --build`, затем запустите `deploy/update-profile-ui.sh`.
Скрипт меняет только навигацию, два старых раздела, загрузку/сброс профиля и
добавляет новые ассеты. Каталог, мастер FunPay, домен API и остальные экраны
сохраняются. Перед заменой проверяется синтаксис Node 22, создаётся архив.
Повторный запуск поддерживается. Неизвестные локальные изменения останавливают
обновление до записи файлов.

Проверки: `node --test app/profile.test.mjs` и `node --test app/*.test.mjs`.
