# Лоты и товары

Раздел использует существующий `state.storeContent` и общий read-only запрос
`syncStoreContent({ silent: true })`. Новых API и записей на FunPay нет.

Текущий рабочий коннектор не получает список лотов: его снимок содержит
`lots: null`, `availableResources.lots: false`. Интерфейс показывает это явно,
а сводка остаётся с прочерками. Пустой полученный массив и недоступный ресурс
различаются. Переходы к Lot Cloner и Mass Price Editor открывают существующие
страницы плагинов и сами ничего не запускают.

## Контракт отображения

Снимок должен иметь `observedAt` и относиться к выбранному магазину.
В `lots` используются существующие поля: `id`, `title`, `category`, `status`,
`priceMinor`, `currency`, `stock`, `sales`, `position`.
Только явно переданные `active` и `paused` считаются известными статусами.
Неизвестные остатки, цены, продажи и позиции не превращаются в нули.
Дубли ID пропускаются. Внешние ссылки генерируются только для числовых ID,
а ссылки из снимка не используются.

Поиск работает по названию, ID и категории. Фильтры: статус, категория, валюта.
Сортировка: исходный порядок, название, цена, остаток. Цены сравниваются только
в одной валюте; пересчёта валют нет. Размер страницы — 10, 20 или 50 лотов.
Карточка деталей показывает те же полученные поля.

## Проверка и обновление

```bash
node --test app/lots.test.mjs
python3 deploy/stage-lots-ui.test.py
```

`deploy/update-lots-ui.sh` сохраняет остальные разделы и локальные правки VPS,
проверяет подготовленные JS в Node 22 через Docker, создаёт резервную копию,
затем устанавливает только модуль лотов и его подключения. Повторная установка
не дублирует скрипты и хуки. Неизвестные границы раздела останавливают обновление.
Сервер API перезапускать не нужно.
