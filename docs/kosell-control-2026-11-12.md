# Окно Kosell и массовая витрина

Рабочая поверхность построена вокруг списка игр и состояния очереди: графитовые уровни, спокойная навигация, оранжевые основные действия, компактная сводка. Вводная часть сокращена, подробные настройки и существующие операции сохранены. Главная страница и её hero не меняются.

В выбранных играх есть группы «Все», «Требуют внимания», «Готовы» и повтор только незагруженных параметров. При повторе сохраняются допустимые ручные значения той же категории. Выборы другой категории не переносятся. Длинные списки значений ищутся по названию: в DOM не создаются тысячи option для каждой игры. Свободный текст не подменяет подтверждённое значение FunPay.

Приостановленная очередь показывает отдельно этап, HTTP и отклонённые поля из сервера. Исторические неопределённые результаты остаются для сверки, проба относится только к ещё не отправленному лоту. Никаких автоматических повторных созданий.

Предпросмотр: `node scripts/preview-kosell-workspace.mjs`, адрес http://127.0.0.1:8101/?scenario=review. Данные там синтетические, обращения к FunPay и реальные действия отключены. Во встроенном браузере проверены повторная загрузка, сохранение всех четырёх игр, заполнение обязательного поля и переход 2/4 → 4/4 готовых. На ширине 390px не обнаружено горизонтального переполнения; временное изменение viewport сброшено.

Установщик меняет два ассета и только их ключи кэша в app/index.html. Неизвестные исходные файлы отклоняются до записи. Создаётся закрытый архив; если публичные ассеты или подключения не подтверждают обновление, файлы возвращаются. Остальная разметка кабинета сохраняется.

97 frontend-тестов и три fixture-проверки установщика проходят локально. Публикация на VPS и работа с реальными лотами пока не подтверждены.

При проверке визуального направления использованы принципы Unslop, Damir Sokolovsky (@heydamir), CC BY 4.0: согласованные отступы, нейтральные поверхности, акцент по функции и содержательные состояния. Сам интерфейс использует действующую стилистику ZetSlay.
