## Реализация

Оформление находится в `app/cabinet-v3`. Взяты токены, шрифт Inter, 3D-ассеты, закатная обложка и CSS компонентов из переданного пакета. Подключены четыре ранее подготовленные иконки тарифов. `production.css` связывает систему с настоящими компонентами кабинета; `production.js` перестраивает оболочку и представления поверх существующих контроллеров.

Состав: группированная боковая панель с мобильным drawer и сворачиванием на desktop; единая верхняя полоса и обложки; профиль с левой колонкой строк; оранжевые карточки каталога по смысловым группам; продуктовая страница плагина с рабочими настройками; отдельные страницы подключения, Telegram, безопасности, документов и прокси. Заказы, сообщения, лоты, события, аналитика, финансы, автоматизация, поддержка, база знаний и административные инструменты сохраняют действующие формы и используют новые основы оформления. Не удаляются поля специализированных плагинов, разрешения и подтверждения операций. Новая панель не показывает «Работает» только на основании флага enabled: выводится точное «Включён».

Для совместимости оставлены реальные обработчики `data-*`, auth/session, загрузка API, серверные права и механизмы неизвестного результата. Экраны безопасности и документов перемещаются вместе с формами, а не дублируются; повторный серверный рендер обновляет их. Редактор профиля сохраняет черновик при отказе сохранения. После выхода отдельные частные экраны очищаются. Ошибка каталога показывает повтор чтения и скрывает устаревшие карточки с ценами.

Не подключаются prototype-адаптеры, генераторы фикстур, переключатели роли/результата, демонстрационные успешные оплаты, локальные вымышленные балансы и очереди. Данные тестовых аккаунтов существуют только в QA-скрипте с перехватом сети. Логика тарифов, цены, покупок, выдачи и очередей не переписывается оформлением. Новых эндпоинтов нет. Серверные функции, отсутствующие в установленном API, этот frontend сам не создаёт.

## Установка

`deploy/start-cabinet-v3.sh FULL_COMMIT_SHA` запускается из `/opt/zetslay-site`. Он получает конкретную ревизию, выполняет preflight и запускает точечный установщик. Сохраняет существующий index, добавляет только ссылки на новый пакет. Уже подключённые workspace/basic-automation модули повторно не грузятся. Их проверенные файлы должны существовать. Существующие app.js/profile.js/plugin-page.js/store-tools.js не заменяются. `.env`, API, база и контейнеры не затрагиваются.

`deploy/cabinet-v3-manifest.json` содержит хеши ассетов и допустимых текущих модулей (Git-основа / публичная версия 14 ноября). Неизвестное изменение host-модуля останавливает установку; оно не затирается. Файлы внутри версии неизменяемы: перед новой редакцией следует изменить версию и заново проверить manifest.

Backup: `/root/zetslay-before-cabinet-v3.*`. Установщик проверяет опубликованные index, JS и CSS по HTTPS; при отказе возвращает прежний index и убирает только созданные им файлы с совпадающими хешами. Для ручного отката: `python3 /root/zetslay-cabinet-v3.XXXXXX/deploy/update-cabinet-v3.py --site /opt/zetslay-site --rollback /root/zetslay-before-cabinet-v3.XXXXXX`. Использовать реальные пути из вывода установки. После ручного отката ассеты остаются для уже открытых вкладок.

14 ноября SSH `root@31.58.118.111` ответил `Permission denied (publickey,password)`. Поэтому публикация на VPS не выполнена и успешным боевым выпуском этот документ не является. После установки нужен вывод установщика и проверка авторизованного кабинета владельцем: подключение, сохранение безопасной настройки, загрузка событий/сообщений/лотов и проверка состояния уже существующих платежей без повторных покупок.
