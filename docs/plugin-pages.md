# Страницы плагинов

«Подробнее», название и обложка карточки ведут на отдельную страницу в кабинете: `/app/#plugins/zetslay.auto-reply`. Ссылка имеет обычный `href`: поддерживаются прямое открытие адреса, перезагрузка и навигация браузера. Кнопка «Назад в каталог» ведёт на `/app/#plugins`.

Открытие происходит в текущей вкладке, поэтому существующая сессия сохраняется. При открытии ссылки в другой вкладке действуют прежние правила авторизации ZetSlay: сессия хранится в `sessionStorage`. Токены не переносятся в URL или `localStorage`.

## Файлы и блоки

- `app/index.html`: каталог `.plugin-catalog`, пустой контейнер `data-plugin-admin-controls`, новая секция `.plugin-page[data-plugin-page]`, подключения `plugin-page.css` и `plugin-page.js`.
- `app/app.js`: проверка `canManagePluginCatalog()`, обработка каталога, карточки с обычными ссылками, маршрутизация в `setView()`, защита действий от повторных нажатий и смены сессии.
- `app/plugin-page.js`: страница, состояния загрузки и ошибки, описание, обложки, разрешения, действия и переход к существующим настройкам. Данные берутся только из `state.plugins`, которое заполняет существующий API каталога.
- `app/plugin-page.css`: классы `plugin-page-*`, `plugin-admin-controls` и отдельные дополнения карточек каталога. Тёмные панели, тонкие границы, янтарные действия; адаптивная колонка действий.
- `app/assets/plugin-covers/{chat,sales,analytics,control}.svg`: четыре иллюстрации категорий. Загруженная администратором растровая обложка имеет приоритет; повреждённое изображение заменяется иллюстрацией.
- `app/plugin-page.test.mjs`: 16 проверок прав, навигации, изображений, форматирования, ошибок и действий.

Основные новые атрибуты: `data-plugin-page`, `data-plugin-page-link`, `data-plugin-admin-controls`, `data-plugin-page-retry`, `data-plugin-cover`, `data-cover-category`, `data-plugin-open-settings`. Существующие `data-plugin-id`, `data-plugin-edit` и `data-cover-plugin` используются для действий и административного редактора.

## Права и состояния

Административные кнопки создаются только при наличии авторизованного пользователя, токена и строгого `canManage: true` из ответа сервера. При выходе, ошибке загрузки прав или отзыве роли кнопки исчезают. Сервер продолжает независимо проверять право записи. Черновики скрыты от пользователей, в том числе по прямой ссылке.

Цена и описание берутся из каталога. Покупка плагинов сейчас не подключена; страница честно сообщает об этом. Доступный модуль устанавливается и включается существующими API, а запланированный модуль имеет отключённую кнопку. «Включён» означает состояние установки в ZetSlay; страница не обещает отправку сообщений на FunPay. Разрешение `replies:queue` предлагает ответ в очередь, live-отправка остаётся отключённой.

Описание поддерживает `**жирный текст**` и строки цитат, начинающиеся с `>`. HTML и значения атрибутов экранируются. Для загруженных обложек принимаются только небольшие PNG/JPEG/WebP в формате data URL; произвольные внешние адреса и SVG из каталога не выполняются.

Страница показывает загрузку до получения каталога, ошибку с повтором при сбое и отдельное состояние отсутствующей карточки. Действия имеют индикатор сохранения и блокируют повторные запросы. При смене аккаунта незавершённая установка не запускает следующий запрос включения для нового аккаунта.

## Проверки

```sh
node --check app/app.js
node --check app/plugin-page.js
node --test app/app.test.mjs app/overview.test.mjs app/orders.test.mjs app/plugin-page.test.mjs
python3 deploy/stage-plugin-ui.test.py
bash -n deploy/update-plugin-ui.sh
```

Локально проходят 77 тестов кабинета, 7 существующих серверных тестов прав каталога и 5 тестов подготовки обновления. Использован Node 24. Браузерный визуальный прогон в среде разработки недоступен. Установка и повторный запуск проверены на двух сохранённых вариантах VPS: с новой «Главной» и с «Главной» плюс «Заказы».

## Обновление VPS

Выполнить на основном VPS под `root`:

```sh
bash <<'SH'
set -euo pipefail
cd /opt/zetslay-site
git fetch origin codex/landing-light-dark-redesign
script=$(mktemp)
trap 'rm -f "$script"' EXIT
git show FETCH_HEAD:deploy/update-plugin-ui.sh > "$script"
bash "$script"
SH
```

Установщик использует фиксированный исходник до обновления плагинов для переноса только нужных изменений в текущий `app.js`. Остальные функции, страницы, адрес API и стили сохраняются. Неизвестная локальная правка останавливает подготовку до изменения сайта. Проверки выполняются на подготовленных файлах через Docker `node:22-alpine`: новая страница, установленные модули «Главной» и «Заказов», а также проверки каталога, входа и демо-тарифа.

Резервная копия: `/root/zetslay-site-before-plugin-page.*.tar.gz`. Ассеты записываются до `index.html`; ошибка записи вызывает восстановление. Backend, vault и настройки сервера не меняются. После успешной установки нажать `Ctrl+F5`; перезапуск Docker Compose не требуется.

Для возврата использовать точный путь к резервной копии, который напечатал установщик:

```sh
cd /opt/zetslay-site
tar -xzf /root/zetslay-site-before-plugin-page.XXXXXX.tar.gz
```

Новые ассеты, оставшиеся после возврата первой установки, не подключаются восстановленным `index.html`.
