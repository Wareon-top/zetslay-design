# Главная кабинета

Изменён только блок `section[data-view="dashboard"]` в `app/index.html`.
Сетка `.overview-grid`: четыре показателя, продажи во всю ширину,
возвраты (две колонки), структура заказов и быстрые действия.
Ниже сохранены списки заказов и баланса. На узких экранах сетка переходит
в две, затем одну колонку для больших панелей; показатели остаются по два.

`app/overview.css` содержит стили `.overview-*`, ограниченные Главной.
`app/overview.js` загружается перед `app.js`. В `renderDashboard()` добавлен
вызов `renderOverview()` с прежним рендером как резервным вариантом.
Другие функции кабинета не изменены.

## Данные и действия

- Источник: `state.storeContent` из существующего `GET /api/v1/funpay/content`.
- `[data-overview-refresh]` вызывает `syncStoreContent({ silent: true })`.
  Повторное нажатие блокируется; ошибка видна рядом с сохранённым снимком.
- `[data-overview-mode]`: суммы по заказам / по датам заказов.
  Даты синхронизации не подставляются вместо дат заказов.
  Календарный график доступен только при наличии дат всех учтённых продаж.
  Дни без данных не считаются днями с нулевыми продажами; линия прерывается.
- `[data-overview-currency]` переключает валюту показателей и графика.
  Валюты не складываются и не конвертируются.
- Быстрые действия используют существующие `data-view-link`.
  Подключение — существующий `data-open-connect`.
- Точные значения графика доступны в раскрываемой таблице.

Сумма продаж: заказы `paid`, `processing`, `delivered`, `completed` с
целочисленной неотрицательной суммой и валютой. Возвраты и отмены исключены.
Средний заказ рассчитывается по тем же заказам. Комиссии не вычитаются:
коннектор их не возвращает. Пропущенные суммы не заменяются нулями.
Учитывается только загруженный снимок (текущий коннектор читает до 100 заказов),
а не вся история магазина. Сравнения с прошлым месяцем, конверсия и категории
не добавлены: API не предоставляет необходимых данных.

## Проверка

```sh
node --check app/app.js
node --check app/overview.js
node --test app/app.test.mjs app/overview.test.mjs
python3 deploy/stage-overview-ui.test.py
bash -n deploy/update-overview-ui.sh
```

45 тестов Node: 32 прежних и 13 новых, включая валюты, возвраты,
отсутствующие даты/суммы, HTML-экранирование, смену аккаунта, ошибки обновления
и вызов существующего read-only API. Ещё пять тестов проверяют подготовку
обновления, сохранение локальных изменений и отказ при неизвестных конфликтах.
Полноценная визуальная проверка в браузере этой среды недоступна:
локальный URL блокируется, поэтому результат требует просмотра после установки.

## VPS

На основном сервере `root@zetslay`:

```sh
bash <<'SH'
set -euo pipefail
cd /opt/zetslay-site
git fetch origin codex/landing-light-dark-redesign
revision=$(git rev-parse FETCH_HEAD)
script=$(mktemp)
trap 'rm -f "$script"' EXIT
git show "$revision:deploy/update-overview-ui.sh" > "$script"
bash "$script"
SH
```

Установщик подготавливает изменения во временной папке, проверяет синтаксис,
13 тестов статистики и четыре проверки входа/демо-тарифа на подготовленном
VPS `app.js`. Затем создаёт резервную копию в `/root` и заменяет файлы,
HTML последним. Изменения остальных разделов, существующий `styles.css`,
настройки API и мастер подключения сохраняются. Неизвестное окончание
`renderDashboard` или маркеры слияния останавливают установку до записи.
Backend, Docker Compose, vault и магазин FunPay не затрагиваются.

После установки откройте `/app/` с Ctrl+F5. Проверка выдаваемых файлов:

```sh
curl -fsS https://zetslay.pro/app/ | rg 'overview\.(js|css)'
curl -fsS https://zetslay.pro/app/overview.js -o /dev/null
curl -fsS https://zetslay.pro/app/overview.css -o /dev/null
```

Если `rg` на сервере отсутствует, используйте `grep -E`.
Для отката распакуйте указанный установщиком архив из `/opt/zetslay-site`.
Архив возвращает прежний HTML и `app.js`; дополнительные ассеты могут остаться,
но прежняя страница их не подключает.
