# Kosell Rent: сохранение настроек

Исправление интерфейса не меняет структуру API, подключённый FunPay-магазин или сохранённый ключ.

- Настройки отправляются одним POST `/api/v1/plugins/kosell-rent/settings`.
- Его подтверждённый ответ используется сразу, без дополнительного GET, способного скрыть успешное сохранение.
- Пока запрос выполняется, кнопки формы заблокированы. Форма не перерисовывается и не теряет введённый текст.
- При ошибке введённые данные остаются в текущей форме; причина появляется рядом с кнопкой «Сохранить настройки».
- Ключ очищается только после подтверждения сохранения. Он не записывается в состояние интерфейса, localStorage или sessionStorage. При закрытии страницы черновик не сохраняется.
- Ошибка поля внутри свёрнутой группы открывает группу и переводит фокус на поле.
- Лимиты, шаблоны, команды, таблица бонусов и зависимости автоматизаций проверяются перед отправкой. Серверная проверка остаётся обязательной.
- Лимит 0 допускается для ручного режима; для автопокупки, продления или бонусов нужен положительный лимит.
- Успешное сохранение ключа подтверждает чтение баланса Kosell, но не создаёт аренду и не списывает деньги.

## Обновление

Запустите `deploy/update-kosell-settings-fix.sh` в `/opt/zetslay-site` с `ZETSLAY_KOSELL_SETTINGS_REVISION`, равной опубликованному коммиту. Установщик проверяет известную версию модуля, готовит изменения отдельно, выполняет тесты в Node 22 через Docker и создаёт архив двух изменяемых файлов перед применением. Неизвестная версия или локальные правки модуля останавливают обновление. `app.js`, стили, обложки и остальные разделы не заменяются. После обновления нажмите Ctrl+F5. Пересборка backend не нужна.

## Проверки

`node --test app/kosell-rent.test.mjs`

`python3 deploy/stage-kosell-settings-fix.test.py`

Тесты проверяют отказ API, сохранение формы, ожидание запроса, двойной клик, неизвестный ответ, поздний ответ статуса, смену аккаунта, валидацию скрытых полей, ограничения расходов и сохранение локальных правок при обновлении.
