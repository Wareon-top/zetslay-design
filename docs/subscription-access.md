# Subscription UI

Isolated `app/subscription-access.js/css` adds server-owned subscription status, date and saved discounts to Finances, a real promo form, administrative grant/extension/revocation on user cards, and promo creation/list/disable on the admin overview. Closed business sections show a dedicated, labelled interface preview for the dashboard, orders, messages or lots and a compact access card. These previews contain no stored account data, fictitious orders, working filters or simulated balances. The real section is hidden and restored with its original hidden states and accessible heading when access is activated. Existing enabled-but-excluded plugins are labelled paused; their off button remains available. Catalogue descriptions, profile, security, support, documents and learning remain accessible.

Trial: 3 days, all shipped non-legendary modules; no perpetual free tier. Four paid plans and prices match the public catalogue. Rarity is not installation status. All functional enforcement is on the API and workers; hiding controls alone is not authorization.

Selecting a finance tariff reads `data-billing-pricing`'s current period and requests an exact server quote. The user may choose one redeemed live discount for that plan. Payment remains explicitly unavailable. No placeholder success, fake topup or client-side access grant exists.

A gift code gives the configured days immediately; a discount alone does not enable the service. Repeated submissions never add time again. Scope checks ignore responses after account change or closing the form. Private state and promo lists clear at logout. Server status refreshes each minute while the page is visible; functional API checks remain immediate, including after downgrade/expiry.

Admin grant requires confirmation checkbox and reason; replacement vs extension is explicit. UUID persists for retries after a lost response. Refresh the user card to begin a separate administrative operation. Creating a promo reveals only fields relevant to its type. Code uniqueness is permanent; expiry and activation count are set by the admin.

Update with `deploy/update-subscription-access-ui.sh` AFTER backend rollout. Script preserves the live HTML's local config and all other JS files, stages and tests before backup/copy, and restores files if copy fails. Browser visuals could not be checked in this environment; DOM/state tests and stage idempotency/preservation checks are included.

The access card uses server eligibility: an available trial offers an explicit 3-day activation, a used trial offers tariffs and a real promo form, and an unknown status offers a read-only eligibility check. Activation reuses the existing trial API, suppresses duplicate clicks, invalidates older status responses and reloads the catalogue/onboarding after success. Preview DOM remains stable across unchanged status checks. On narrow screens the activation card comes first; reduced-motion preference disables the entry animation.

Plan promo codes extend the same active tier or immediately upgrade to a higher catalogue rank (Start → Growth → Pro → Maximum). An upgrade replaces the current tier; its exact duration starts at redemption, without converting or transferring the old remaining days. The promo dialog explains this before submission. A lower-tier code is rejected while a higher tier is active and remains unused. Expired tiers and the one-time trial can be replaced. Replaying a consumed code only returns the current workspace; it cannot restore an earlier tier or add days. The installer retains the existing script order so the wallet checkout wrapper remains active.
