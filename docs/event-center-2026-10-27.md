# Event centre experience

The Lovsel screenshot supplied by the owner provides a compact two-pane reference: a search field, read filters, category chips, grouped unread/read rows and a detail pane. Interactive inspection through the selected Browser extension was unavailable, so no claims are made about unobserved competitor behaviour.

ZetSlay now uses readable graphite surfaces with restrained orange accents, compact timestamped rows, separate new/read groups, meaningful attention badges, a fixed control area and independently scrolling panes. Below 900px the selected detail replaces the list and exposes a back button. Search, categories and filters work together; arrows select events, `/` focuses search and Escape closes the detail. The view distinguishes an empty feed, a completed inbox, empty search, loading and failed refresh. Persisted event summaries link to the existing order, conversation, support, proxy and automation views; the feed does not invent full message bodies or execute sales.

The feed controller cancels obsolete reads, rejects stale account/filter results, bounds requests to 15 seconds, retains successful data after failures and queues read marks when events are opened quickly. Failed read marks remain visibly unread with an explicit retry. Read-all sends the displayed server watermark; later arrivals remain unread. A selected detail remains available after it leaves the unread filter. Pagination returns to an existing page after the final unread row disappears.

The paired starter pins core `ca95575ee11d539a2c83a1631358438180adac72` and runs its existing tested event API installer. This supports installations where the event tables or projector have not yet been deployed. It patches only the event integration, adds its two event tables if absent and preserves the running authentication, payment, proxy and other modules. It does not change MFA duration. Initial archived history is read by default; later observed events can be unread. Events remain an observation history rather than a complete ledger.

The UI installer verifies asset digests and the previous event module, preserves all installed HTML outside versioned asset includes, keeps the current global workspace stylesheet and replaces only the event client plus its scoped stylesheet. A verified private archive and retained API container support rollback. No real purchase, customer message or supplier action is part of installation or browser testing.

Verification includes feed race/failure/scope tests, order/message/proxy regressions, byte-preservation, idempotence and installer rollback tests, the pinned event API's existing patch/probe tests, and a synthetic desktop/mobile browser scenario. Production deployment is a separate operator step.
