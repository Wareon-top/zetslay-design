# Раздел «Заказы»

Тёмная таблица с тонкими разделителями, цветными аватарами покупателей и четырьмя карточками показателей. Раздел использует существующий снимок `state.storeContent`; новые API и действия на FunPay не добавлены.

## Файлы и подключения

- `app/index.html`: только секция `data-view="orders"`, подключения `orders.css` и `orders.js`, версия кэша `app.js`.
- `app/orders.css`: классы `orders-page-*`; адаптивная таблица, карточки показателей и диалог заказа.
- `app/orders.js`: модель, поиск, фильтры, сортировка, страницы, карточка заказа и обновление снимка.
- `app/app.js`: вызов `renderOrderWorkspace()` в начале `renderOrders()` и общая обёртка `syncStoreContent()`. Существующее тело запроса сохранено в `readStoreContent()`.
- `app/orders.test.mjs`: 16 проверок данных, состояния интерфейса и запросов.

Основные атрибуты: `data-orders-workspace`, `data-orders-search`, `data-orders-filter`, `data-orders-currency`, `data-orders-sort`, `data-orders-page`, `data-orders-refresh`, `data-order-open`, `data-order-dialog`, `data-order-close`.

## Правила данных

Карточки показывают все заказы текущего снимка, независимо от фильтров. «В работе» включает `paid`, `processing`, `delivered`; «Завершены» — только `completed`; «Возвраты» — только `refunded`. Неизвестный статус остаётся в «Всех заказах» с подписью «Без статуса».

Поиск проверяет номер заказа, товар и покупателя. Счётчики вкладок учитывают поиск и выбранную валюту. Доступны страницы по 10, 20 или 50 строк и сброс фильтров.

Сортировка по сумме доступна, когда известные суммы отфильтрованных заказов относятся к одной валюте. Сортировка по дате использует только переданные даты; заказы без даты показываются в конце. Время получения снимка не подставляется вместо даты заказа. Суммы разных валют не сравниваются и не суммируются.

Карточка заказа открывается нажатием на номер или стрелку. Показывает товар, покупателя, статус, сумму и доступные даты. Тексты из снимка экранируются. При выходе или смене аккаунта диалог, фильтры и состояние запросов очищаются.

«Обновить заказы» вызывает существующий `syncStoreContent({ silent: true })`. Одновременное обновление с «Главной» и из «Заказов» использует один запрос в рамках текущей сессии. При ошибке остаётся предыдущий снимок и появляется сообщение с возможностью повторить обновление. Это read-only экран: изменения статусов, отправки сообщений и финансовых операций здесь нет.

## Проверки

```sh
node --check app/app.js
node --check app/orders.js
node --test app/app.test.mjs app/overview.test.mjs app/orders.test.mjs
python3 deploy/stage-orders-ui.test.py
bash -n deploy/update-orders-ui.sh
```

Установщик проверяет подготовленные файлы через Docker `node:22-alpine`: 16 тестов заказов, 13 тестов Главной и отдельные проверки входа и демо-тарифа. Локальные проверки выполнялись на Node 24. Автоматический визуальный прогон в браузере в среде разработки не был доступен.

## Установка на VPS

Нужны уже установленная новая «Главная», Python 3, Docker, Git и доступ к ветке дизайна. Выполнить на основном VPS под `root`:

```sh
bash <<'SH'
set -euo pipefail
cd /opt/zetslay-site
git fetch origin codex/landing-light-dark-redesign
script=$(mktemp)
trap 'rm -f "$script"' EXIT
git show FETCH_HEAD:deploy/update-orders-ui.sh > "$script"
bash "$script"
SH
```

Установщик готовит новую секцию поверх текущих файлов VPS и запускает тесты до изменения сайта. Он сохраняет локальный адрес API, «Главную», существующие стили, вход и мастер подключения. При неизвестной версии нужной функции установка останавливается до записи файлов. Повторный запуск не дублирует ассеты или обёртки запросов.

Резервная копия появится в `/root/zetslay-site-before-orders.*.tar.gz`. Ассеты записываются перед `index.html`, каждый файл заменяется через временный файл. Ошибка записи вызывает восстановление сохранённых файлов. Backend и конфигурация сервера не меняются; перезапуск Docker Compose не требуется. После установки открыть кабинет с `Ctrl+F5`.

Для ручного возврата использовать точный путь к резервной копии, который напечатал установщик:

```sh
cd /opt/zetslay-site
tar -xzf /root/zetslay-site-before-orders.XXXXXX.tar.gz
```

Если это была первая установка, оставшиеся новые `orders.*` после возврата не подключаются восстановленным `index.html`.
