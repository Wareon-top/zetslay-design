# Сообщения FunPay

Раздел работает поверх `state.storeContent.messages` и архива полученной переписки. Свежий снимок использует `syncStoreContent({silent: true})` → `GET /api/v1/funpay/content`; страницы архива читаются через реализованный `GET /api/v1/funpay/messages?limit=100&before=...`. Оба маршрута требуют сессию, workspace/store определяются сервером. Записи на FunPay и доступа интерфейса к секретам нет.

- `app/index.html`: секция `data-view="messages"`, корневой `data-messages-workspace`, список, поиск, фильтры последнего отправителя, поиск внутри переписки и native dialog.
- `app/messages.js`: нормализация реального снимка, группировка по `threadId`, безопасный вывод текста, сохранение выбранного диалога, обработка обновления и мобильной навигации.
- `app/messages.css`: изолированные классы `messages-page-*`; две колонки на компьютере, список / чат с кнопкой назад на телефоне.
- `app/app.js`: только два делегирующих вызова в `renderConversations` и `renderActiveConversation`. Общий запрос данных уже защищён от дублирования между разделами.

В списке отображаются количество загруженных сообщений и текст последнего сообщения. Фильтры «Покупатель» / «Магазин» описывают последнего отправителя, а не непрочитанные сообщения. Точные даты показаны при валидном `createdAt` не позже `observedAt`. Текстовый `sourceDateLabel` показывается как на FunPay, без добавления года/часового пояса и без фиктивного datetime. Если даты неполные, сообщения сортируются по числовым ID FunPay; для ненумерованных данных остаётся порядок источника. Время синхронизации не заменяет время сообщения. Статусы присутствия, прочтения и полная история не обещаются. Композер отключён, поскольку коннектор read-only.

Поиск локальный: по имени, ID диалога и тексту загруженных сообщений. Поиск в чате выделяет буквальные совпадения и позволяет переходить между ними. Весь текст FunPay экранируется, включая результаты поиска. При смене сессии сбрасываются выбор, фильтры, результаты поиска и карточка диалога. Ошибка обновления оставляет предыдущий снимок и разрешает повтор.

## Проверки

```sh
node --check app/messages.js
node --test app/messages.test.mjs app/app.test.mjs app/overview.test.mjs app/orders.test.mjs app/plugin-page.test.mjs
python3 deploy/stage-messages-ui.test.py
bash -n deploy/update-messages-ui.sh
```

Модуль имеет 26 тестов модели и взаимодействий с DOM-заглушками. Они проверяют работу со снимком, XSS, поиск, смену диалога, мобильную навигацию, сохранение прокрутки, ошибки и смену сессии; это не визуальный браузерный тест.

## Обновление существующего VPS

```sh
bash <<'SH'
set -euo pipefail
cd /opt/zetslay-site
git fetch origin codex/landing-light-dark-redesign
script=$(mktemp)
trap 'rm -f "$script"' EXIT
git show FETCH_HEAD:deploy/update-messages-ui.sh > "$script"
bash "$script"
SH
```

Установщик переносит только раздел Сообщения, ассеты и два hook. На старом кабинете добавляет общую обёртку чтения, сохраняя тело существующего запроса. Дизайн остальных разделов, локальные исправления авторизации/коннектора, адрес API и CSS сохраняются. Подготовленные файлы проходят проверки в `node:22-alpine` до записи; резервная копия создаётся в `/root`. При ошибке записи восстанавливается копия. Git checkout/reset и перезапуск сервисов не нужны.

После установки обновить кабинет через Ctrl+F5. Ручная проверка: открыть загруженный диалог, найти фразу, изменить фильтр, обновить снимок, проверить возвращение к списку на телефоне и отсутствие отправки сообщений. Файлы меняются по одному (HTML последним); при уже открытом старом кабинете следует перезагрузить вкладку после завершения обновления.

## Архив и автообновление

Открытый видимый раздел обновляется каждые 30 секунд. При скрытии вкладки, переходе в другой раздел, выходе или потере подключения таймер останавливается. После ошибок интервал растёт до 60/120 секунд. Обновление ждёт завершения запроса; несколько кабинетов одного workspace на сервере делят одновременно выполняющийся снимок. Автоматизация плагинов не включается.

Кнопка «Загрузить более ранние сообщения» постранично читает архив, сохраняя выбранный диалог и загруженную историю при последующих обновлениях. «Открыть сохранённую переписку» доступна при отсутствии свежего снимка, включая ошибки подключения, пока магазин присутствует в состоянии аккаунта. Архив не подменяет статистику других разделов при таком открытии. Поиск работает по загруженной части, её размер и общее число архивных сообщений показываются рядом с кнопкой.

Архив накапливается с момента внедрения и содержит только полученные сообщения. Импорт всей прошлой истории и загрузка вложений не заявляются. Даты могут отсутствовать у сообщений без собственного заголовка FunPay. Сначала обновите API скриптом `deploy/update-messages-api.sh` из core; затем используйте установщик UI выше.
