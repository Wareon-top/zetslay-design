# Сообщения в кабинете

Владелец активного тарифа может читать переписку и вручную отвечать из веб-кабинета. Отправка использует отдельный ограниченный исполнитель записи. Read-only коннектор, просмотр архива и обновление диалога не отправляют покупателям сообщения и не включают автоматические плагины.

Перед отправкой сервис читает профиль и выбранный чат через сохранённый прокси. Чат должен присутствовать в актуальном списке контактов FunPay и содержать сообщение покупателя. Проверяется закреплённый продавец, действующий тариф, сессия, неизменность ключа и прокси, срок управляемого прокси. Чаты вне текущего списка контактов требуют проверки на FunPay; угадывание получателя по имени не используется.

Каждая отправка имеет идентификатор `wmsg_…`, привязанный к владельцу, магазину, чату и хэшу текста. В PostgreSQL сначала сохраняется подготовка, затем намерение записи с последним наблюдавшимся ID. Разрешена одна незавершённая отправка на диалог. POST на FunPay выполняется один раз; подтверждением считается новый ID сообщения продавца с точным совпадением текста. Кнопка и сервер защищают от повторного клика; одинаковые успешные ответы в течение десяти секунд также не дублируются.

После неопределённого ответа повтор не запускается автоматически. «Сверить с FunPay» только читает сообщения и ищет единственное подтверждение после сохранённого ID. При потере ответа браузером «Получить результат» повторяет запрос с тем же идентификатором: сохранённая операция возвращается без повторной записи. Кнопка «Я проверил переписку» требует явного подтверждения и разблокирует ввод; она не отправляет текст. Повторный ответ остаётся отдельным ручным действием владельца.

Ограничение — 1000 символов UTF-16. Токены ботов, Golden Key и адреса прокси с реквизитами не принимаются. Вложения и массовая рассылка не поддерживаются.

Сообщения с числовыми ID сортируются по ID FunPay с использованием BigInt. Полные ISO-даты служат запасным порядком только при отсутствии числовых ID у всей группы. Неполные даты остаются текстом источника; год и часовой пояс не выдумываются. Системное событие не скрывает последний запрос покупателя из фильтра ожидания ответа. «Ждут ответа» — фильтр по последнему человеческому сообщению, не статус прочтения FunPay.

Интерфейс сохраняет отдельные черновики и закрепления в sessionStorage текущей вкладки с областью user + store. При выходе они очищаются. Текст с признаками секретов не сохраняется. Переключение диалога во время отправки не меняет получателя. Запоздавшие ответы отсеиваются по сессии, магазину и поколению интерфейса.

Обновление открытого раздела каждые 30 секунд читает сохранённый архив и выбранный диалог. Оно не выполняет полную синхронизацию магазина при каждом ответе. Новые диалоги появляются после их чтения существующим фоновым worker или ручной синхронизации списка кнопкой рядом с заголовком «Диалоги». При первом открытии пустого архива выполняется первичная синхронизация. Наличие всей прошлой истории не обещается: сохраняется фактически прочитанная переписка, а выбранный live-диалог содержит до 50 последних сообщений. Более ранние сохранённые сообщения доступны через историю конкретного диалога.

Backend: deploy/update-messages-workspace.sh. Интерфейс: deploy/update-messages-workspace-ui.sh в репозитории дизайна. Обновление API запускает полный набор тестов и проверку на одноразовом PostgreSQL до миграции рабочей базы. Обновление интерфейса сохраняет app.js, остальные разделы и локальные настройки сайта.
