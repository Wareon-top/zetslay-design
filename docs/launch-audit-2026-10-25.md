# ZetSlay: аудит перед продвижением, 25 октября 2026

Статус: исправления подготовлены в репозиториях. Установка на VPS требует запуска опубликованного `deploy/start-launch-readiness.sh`. Проверка исходников, автоматические тесты и публичные HTTP-проверки не подтверждают успешную реальную оплату или работу конкретного подключённого магазина.

## Что проверено

Публичные главная страница, вход, документы, API health и границы доступа; ссылки и ресурсы сайта; код входа и восстановления сессии; существующие проверки подключения бота, покупок, поздних подтверждений платежей, разграничения аккаунтов и автоматизации; зависимости Node; установка и возврат к прежнему варианту.

164 связанных публичных ресурса при проверке ответили без HTTP-ошибок. Отдельно обнаружены 404 на `/legal/terms.html`, `/robots.txt`, `/sitemap.xml`. Версия и хеш опубликованных документов на сайте совпадают с `/api/v1/legal/status`.

Обновление сохраняет текущие настройки и прочие исправления работающего API. Две зависимости устанавливаются из отдельного lock-файла с проверкой целостности. Остальной набор node_modules не переустанавливается. HTML изменяется точечно на сервере, включая частные тексты и актуальные реквизиты. Новый API сначала проверяется отдельно: HTTP-парсер, адреса почты, кошельки, PostgreSQL в read-only-транзакции, Redis PING при наличии конфигурации. При незавершённой покупке прокси переключение останавливается. Прежний контейнер сохраняется; сбой проверки нового API запускает возврат.

## Что остаётся открытым

1. **TON → Zod:** npm audit продолжает показывать две high-записи для одной транзитивной цепочки. Совместимого исправления Zod 3 в используемом TON SDK нет. Загрузка ненужных HTTP-клиентов и их парсеров из кошельков исключена и проверена тестом. Это снижение доступности проблемного пути, а не полное устранение предупреждения. Нельзя объявлять зависимости полностью чистыми или скрывать аудит.
2. **Сведения об обработке данных:** публичный API возвращает `processorNamesVerified=false` и `localizationReviewed=false`. Требуется подтвердить фактических обработчиков и размещение данных; автоматически менять эти отметки без проверки нельзя. Совпадение версий документов не является подтверждением юридической готовности.
3. **Реальный клиентский путь:** не подтверждены в этой сессии доставка писем, вход через настоящий Telegram, подключение реального магазина, платёж с реальным подтверждением, доставка купленного прокси и выполнение автоматизации на живом заказе. Нужна контрольная проверка с отдельным тестовым аккаунтом и заранее заданным бюджетом, без воздействия на заказы покупателей.
4. **Эксплуатация:** не подтверждены восстановление базы из резервной копии, оповещения о сбоях и поведение под рекламной нагрузкой. Наличие архива само по себе не доказывает возможность восстановления.

## Решение о продвижении

После установки исправлений можно проводить ограниченный запуск с сопровождением первых пользователей. Увеличивать рекламный бюджет следует после подтверждения полного клиентского пути и восстановления резервной копии. Критерий — успешные регистрации, подключения и оплаченные активации без ручного ремонта, а не число просмотров главной страницы.

Сначала фиксировать агрегированные переходы «регистрация → подключение → активированный пробный период → первая полезная автоматизация → оплата» и причины отказов. Секреты, тексты личных сообщений, токены и прокси-реквизиты в такую аналитику не включать. Новые внешние системы аналитики в рамках этого обновления не подключались.

## Установка и возврат

Запускать из `/opt/zetslay-site` с закреплённой ревизией frontend через `deploy/start-launch-readiness.sh`. Скрипт сам получает закреплённую ревизию backend, предварительно проверяет совместимость сайта и запускает отдельное задание systemd. Разрыв SSH или Ctrl+C просмотра журнала не прекращает это задание.

Успех подтверждён только после строки «Готово: исправления аудита установлены» и проверки сайта после Ctrl+F5. Пути резервных копий выводятся в журнал. Архив frontend сопровождается `.absent`: при ручном возврате сначала восстановить архив, затем удалить перечисленные там файлы, отсутствовавшие до установки. Прежний контейнер API и приватная копия его конфигурации сохраняются отдельно. Не удалять работающие контейнеры и базы командой compose down.
